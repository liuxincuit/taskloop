# Spec Delta

## Purpose

定义运行状态与历史的持久化方式，使宿主进程重启后仍能展示此前的执行记录，并正确区分"已中断"与"仍在中"的任务。

## ADDED Requirements

### Requirement: 状态落盘在用户目录

系统 SHALL 将循环状态、任务历史与日志写入用户主目录下的 `.taskloop` 目录。

#### Scenario: 状态文件位置

- **WHEN** 系统写入运行状态
- **THEN** 状态保存在 `~/.taskloop/state.json`

#### Scenario: 日志位置

- **WHEN** 系统写入运行日志
- **THEN** 日志保存在 `~/.taskloop/logs/` 目录下

#### Scenario: 目录不存在

- **WHEN** `~/.taskloop` 目录不存在
- **THEN** 系统自动创建该目录及其所需子目录

### Requirement: 重启后恢复历史

系统 SHALL 在启动时读取已有的状态文件，恢复任务历史与日志后继续运行。

#### Scenario: 重启后查看历史

- **WHEN** 宿主进程重启并读取到此前保存的状态文件
- **THEN** 页面展示之前各轮次的执行记录

#### Scenario: 状态文件损坏

- **WHEN** 状态文件无法解析
- **THEN** 系统以空历史启动，并保留损坏文件以便排查，`MUST NOT` 因状态文件损坏而无法启动

### Requirement: 中断任务被标记

系统 SHALL 在启动时把状态文件中仍标记为执行中的任务改为已中断，`MUST NOT` 将其展示为正在执行。

#### Scenario: 进程被强制终止

- **WHEN** 宿主进程在任务执行期间被强制终止，随后重新启动
- **THEN** 该任务的历史记录显示为已中断，而不是执行中

### Requirement: 对话全文不重复存储

系统 SHALL 只在状态文件中保存任务标识与元数据，agent 的完整对话内容 MUST 依赖 SDK 自身的会话文件。

#### Scenario: 页面查看历史任务

- **WHEN** 用户展开一个历史任务的详情
- **THEN** 系统依据记录中的会话文件位置读取对话内容，而不是从状态文件读取

#### Scenario: 状态文件体积

- **WHEN** 系统累计处理了大量任务
- **THEN** 状态文件只随任务记录数增长，不随对话长度增长

### Requirement: 历史与日志有保留上限

系统 SHALL 对任务历史条数与内存日志条数设置上限，超出后丢弃最旧的记录。

#### Scenario: 任务数量超过上限

- **WHEN** 任务历史条数达到上限后又有新任务完成
- **THEN** 系统丢弃最旧的任务记录并写入新记录

#### Scenario: 日志超过上限

- **WHEN** 运行日志条数达到上限后又有新日志产生
- **THEN** 内存中的日志环形缓冲丢弃最旧条目

### Requirement: 写入失败不中断执行

系统 SHALL 在状态写盘失败时记录错误并继续执行，`MUST NOT` 因写盘失败终止循环。

#### Scenario: 磁盘不可写

- **WHEN** 状态文件所在路径不可写
- **THEN** 系统记录写盘失败，循环继续处理后续轮次
